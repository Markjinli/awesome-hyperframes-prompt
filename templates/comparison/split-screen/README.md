# Split Screen — 分屏对比

> 左右分屏或上下分屏展示「之前 vs 之后」「代码 vs 输出」「传统方案 vs 新方案」的对比。适合产品对比、效率展示、技术升级说明。

## 效果

15-25 秒的分屏对比视频。画面分为左右两个区域，同时展示两个方案/状态，通过中间分隔线的移动突出差异或优势。适合产品对比、效率提升展示、技术方案说明。

## 适用场景

- 产品 vs 竞品对比
- 新版本 vs 旧版本功能对比
- 代码量对比（少代码 vs 多代码）
- 效率提升可视化（之前 N 步 → 之后 1 步）

## Prompt 模板

````markdown
使用 HyperFrames 创建一段分屏对比视频。

## 基础参数
- 时长：20 秒
- 分辨率：1920x1080
- 帧率：30fps
- 风格：现代极简对比

## 对比主题
- 对比类型：[产品 vs 竞品 / 新方案 vs 旧方案 / 代码量对比 / 效率对比]
- 左侧标题："[方案 A 名称，如 Traditional Way]"
- 右侧标题："[方案 B 名称，如 With [产品名]]"
- 核心差异数据：[具体对比点，如 "500 lines → 50 lines"]

## 视觉设计

**布局**
- 初始状态：严格 50:50 分屏
- 左右各有标签栏（高度 80px）
- 左标签：灰色调 #555555
- 右标签：品牌强调色 [#XXXXXX]
- 中间分隔线：2px 白色半透明

**左侧（方案 A）— 展示传统/旧方案**
- 色调：冷灰色调（去饱和，略显暗淡）
- 内容：[旧方案的界面/代码/流程图]
- 整体氛围：功能可用但繁琐
- 入场动画：从左侧屏外滑入

**右侧（方案 B）— 展示新产品/新方案**
- 色调：鲜活饱和
- 内容：[新方案的界面/代码/流程图]
- 整体氛围：简洁、现代、高效
- 入场动画：从右侧屏外滑入

## 动画节奏

**0-2s：分屏入场**
- 左右两部分同时从屏幕外滑入
- 中间分隔线以发光效果出现
- 标签栏文字淡入

**2-6s：并列展示**
- 左右内容各自展示
- 左侧可能展示繁琐的步骤（多个步骤/大量代码）
- 右侧展示简洁的解决方案
- 两侧内容同时滚动/变化，但节奏不同

**6-12s：分隔线移动**
- 中间分隔线开始向右移动（从 50% → 30% 位置）
- 左侧被压缩，内容逐渐被裁切
- 右侧扩大，展示更多细节
- 移动使用 power4.inOut，1.5s 缓慢推进
- 传递信息：新方案正在「挤出」旧方案

**12-16s：全屏展示右侧**
- 分隔线移到 100%（左侧完全消失）
- 右侧全屏展示新方案
- 关键数据/指标用大字展示：
  "[数字]" + "[描述]"（如 "10× faster", "50 lines of HTML"）
- 数字从 0 滚动到目标值

**16-20s：End Card**
- 全屏品牌色背景
- 产品名 + 主 CTA
- "[产品名] — [一句话价值]"
- 底部署名/URL

## 数据可视化
在动画过程中，在底部展示关键对比指标：

| 指标 | 方案 A | 方案 B | 优势 |
|------|--------|--------|------|
| [指标1] | [值A] | [值B] | [倍数]× |
| [指标2] | [值A] | [值B] | [百分比]% |

- 指标栏在分隔线开始移动时出现
- 方案 B 的值用品牌强调色高亮

## 转场
- 入场：左右两部分滑动入场（slide from sides）
- 分隔线移动阶段：自然过渡
- End Card：方案 B 全屏后 → Cross Warp Morph 到 End Card

## 音频
- 分隔线移动时：低音上升（sub-bass rise）
- 全屏展示时：和弦 hit
- 数据滚动时：轻量计数音效

## 技术注意事项
- 左右两部分在独立的容器中，通过 CSS clip-path 或 overflow 控制可见区域
- 分隔线位置通过 GSAP 动画控制
- 数据计数使用 GSAP counter 效果
- 所有 GSAP timeline 注册到 window.__timelines
````

## 关键技巧

- **信息不对等是故意的**：左边用灰色调、更多文字、更复杂的布局，右边用鲜艳色彩、更大字体、更简洁的布局。视觉设计本身就是论据
- **分隔线移动的节奏**：先停 4s 让观众理解对比内容，然后缓慢移动（1.5s），最后加速（0.5s）。不要一开始就移
- **数据可视化放大论点**：底部指标栏用具体数字量化优势——"10× faster" 比 "更快" 有力 100 倍
- **左边不是丑，是「复杂」**：不要让方案 A 看起来很烂（那会显得不公正），让它看起来「功能齐全但复杂」。右边是「同样功能但简洁」

## 自定义方法

1. 修改对比主题和标题
2. 替换方案 A 和方案 B 的具体内容
3. 调整分隔线移动的时间点和速度
4. 修改对比数据指标
5. 调整颜色方案（左灰右彩是最经典的选择）
